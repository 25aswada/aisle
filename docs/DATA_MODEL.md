# Data model

Milestone 0 provides Postgres. Milestone 1 stores retailers and the stores that belong to them.

Item search is not in this milestone. This schema has no item, category, aisle, list, user, or session tables.

The API in `API.md` reads this model. It does not expose a retailer route. Clients receive the retailer as `retailer_name` on each store. `distance_miles` is computed for nearby search and is not a column.

## retailers

A retailer is a brand, such as a grocery chain.

| Column | Type | Constraints |
| --- | --- | --- |
| id | uuid | Primary key. Generated by the database. |
| name | text | Not null. Unique. |

`name` is the string the API returns as `retailer_name`.

## stores

A store is one physical location of a retailer.

| Column | Type | Constraints |
| --- | --- | --- |
| id | uuid | Primary key. Generated by the database. |
| retailer_id | uuid | Not null. Foreign key to `retailers.id`. |
| name | text | Not null. |
| address | text | Not null. Single display line. |
| latitude | double precision | Not null. WGS84 degrees, -90 through 90. |
| longitude | double precision | Not null. WGS84 degrees, -180 through 180. |

`name` is the store label. It can match the retailer or name a specific location.

`stores.retailer_id` is indexed. Deleting a retailer is restricted while any store references it (`ON DELETE RESTRICT`).

Nearby search calculates miles in the query from `latitude` and `longitude`. The haversine radius is 3958.8 miles, as specified in `ARCHITECTURE.md`.

## Identifiers in JSON

`stores.id` is serialized as a lowercase UUID string (`8-4-4-4-12`). `retailers.id` stays in the database and is not a response field.
